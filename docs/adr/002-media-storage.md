# ADR-002: Хранилище сырых и готовых видео

**Status:** Accepted

## Context

Сырое видео с телефона может весить сотни МБ – несколько ГБ. Telegram Bot API ограничивает загрузку до 50 МБ и скачивание (`getFile`) примерно до 20 МБ — передавать исходники через тело Telegram-сообщения нельзя (Technology Audit, раздел «Telegram»). Нужно внешнее хранилище, доступное облачному исполнителю (Cloud Routine) без раздувания git-репозитория бинарными файлами.

Из Technology Audit: Google Drive MCP-коннектор — AVAILABLE, официально документирован как пример коннектора Claude Code, подключается через `claude.ai/customize/connectors`, коннекторы аккаунта по умолчанию доступны в каждой Routine. Официального first-party S3/R2 MCP-коннектора от Anthropic не найдено — статус UNKNOWN, есть только непроверенные сторонние реализации.

## Decision

Использовать **Google Drive** (через MCP-коннектор) как единственное хранилище сырых и готовых видео в MVP. Роман загружает исходник в Drive и присылает боту ссылку; агент читает и пишет туда же через MCP.

## Consequences

- Нулевая дополнительная стоимость и нулевая инженерная работа по интеграции — коннектор уже есть в Anthropic Directory.
- Видео никогда не попадает в git-репозиторий — репозиторий остаётся лёгким.
- Зависимость от квот Google API (не оценивались отдельно в аудите) — если станут узким местом, пересмотреть в сторону S3/R2, но только после того, как появится проверенный официальный или надёжный сторонний MCP-коннектор (сейчас статус UNKNOWN).
- Local Bot API Server (снятие лимита файлов Telegram) сознательно не выбран — требует отдельного постоянного сервера, избыточная инженерная работа при наличии рабочей альтернативы через ссылку на Drive.
