# ADR-001: Язык и фреймворк для кода автоматизации

**Status:** Accepted

## Context

Раздел 6.6 исходного ТЗ (`docs/TZ_AI_Company_Hybrid.md`) описывает структуру монорепозитория (`/apps`, `/packages` с именами вроде `agents`, `ai`, `database`) — это конвенция, характерная для JS/TS-инструментов монорепо (Turborepo/Nx/pnpm workspaces), но выбор языка формально не зафиксирован. Одновременно из Technology Audit видно, что весь реалистичный стек MVP уже тяготеет к JS/TS: Cloudflare Workers (мост Telegram→GitHub) пишется на JS/TS, GitHub Actions workflow — YAML + shell/JS, Claude Agent SDK имеет официальный TypeScript-пакет наравне с Python.

## Decision

Использовать **TypeScript/Node.js** для всего кода автоматизации (Cloudflare Worker, любые вспомогательные скрипты пайплайна, будущий n8n custom-node при необходимости). Структуру репозитория из раздела 6.6 ТЗ зафиксировать как есть (`/apps`, `/packages`), не как черновик.

## Consequences

- Один язык на весь стек — не нужно переключаться между Python и TS для разных компонентов моста/пайплайна.
- Claude Agent SDK и Cloudflare Workers одинаково хорошо поддерживают TS — не теряем интеграционных возможностей.
- Если в будущем понадобится тяжёлая ML/CV-обработка видео (не предвидится в MVP-объёме — весь видео-монтаж идёт через FFmpeg-CLI, вызываемый из Bash, а не через Python-библиотеки) — это решается вызовом внешнего процесса, не требует смены основного языка.
