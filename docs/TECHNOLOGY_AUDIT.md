# Technology Audit — AI-компания ROMAN

Этот документ фиксирует результаты Technology Audit (Фаза 0 по ТЗ проекта): проверенные факты о доступности, стоимости и API/MCP-интеграции инструментов, необходимых для запуска автоматизированного контент-конвейера "ROMAN RAW" — от загрузки сырого видео до публикации версий на YouTube Shorts, Instagram Reels, TikTok, Facebook Reels, X и Telegram, с управлением через Telegram и «командным центром» в приватном GitHub-репозитории. Статусы (AVAILABLE / LIMITED / PAID / NOT_AVAILABLE / UNKNOWN) приводятся как есть, без смягчения — это карта реальных ограничений, а не список пожеланий.

## Telegram

| Инструмент | Статус | Стоимость | API/интеграция | Зачем нужен |
|---|---|---|---|---|
| Telegram Bot API (ядро: сообщения, webhook, getUpdates) | AVAILABLE | Полностью бесплатно с 2015 г., без подписок и платы за сообщение. Rate limit по умолчанию ~30 сообщений/сек на бота (1 сообщение/сек в один чат); входящие обновления в лимит не считаются. Массовая рассылка сверх лимита — платно через Paid Broadcasts (не требуется для ROMAN). | Официальный REST API. Поддерживает push-модель (`setWebhook`, HTTPS, порты 443/80/88/8443, до 100 одновременных соединений) и pull-модель (`getUpdates`, long polling, limit 1–100). | Базовый канал "командного центра" — Роман загружает видео и отдаёт команды через бота; webhook/getUpdates нужен, чтобы облачный конвейер реагировал на сообщения без участия ноутбука Романа. |
| Telegram Bot API — лимиты на размер файла (видео/большие файлы) | LIMITED | Бесплатно, но с жёсткими ограничениями стандартного облачного Bot API: загрузка (отправка) до 50 МБ; скачивание через `getFile` — **проверено эмпирически (28.08.2026): ровно 20 МБ** (20 МБ — успех, 21 МБ — `400 Bad Request: file is too big`). | Тот же Bot API (`getFile`/`sendVideo`/`sendDocument`). | Критично для MVP: сырое видео с телефона может весить сотни МБ–несколько ГБ, через обычный облачный Bot API его нельзя ни принять, ни выдать напрямую — нужен обходной путь (см. Local Bot API Server) или передача видео не через бота (облачное хранилище + ссылка). |
| Self-hosted Local Bot API Server (`tdlib/telegram-bot-api`) | LIMITED | Софт бесплатный, open-source. Снимает лимит на скачивание и поднимает загрузку до ~2000 МБ. Но требует своего постоянно работающего сервера (VPS/контейнер) — не бесплатно в инфраструктурном смысле. | Тот же Bot API, но self-hosted; можно развернуть в облаке (Docker) как отдельный постоянный сервис, независимый от ноутбука Романа. | Реалистичный путь снять лимит 20/50 МБ для полноразмерных исходников и готовых роликов — но добавляет новый компонент инфраструктуры, который нужно где-то хостить и поддерживать. |
| Официальный Telegram-плагин для Claude Code (MCP, `anthropics/claude-plugins-official`) | LIMITED | Бесплатный (open source). Требует Bun runtime и запуск `claude --channels plugin:telegram@claude-plugins-official`. | MCP-инструменты reply/react/edit_message через Telegram-бота; входящие фото сохраняются локально, файлы до 50 МБ. Критично: это stateful-соединение к ЛОКАЛЬНОЙ работающей сессии Claude Code — НЕ облачный/scheduled-агент, не работает при выключенной сессии/ноутбуке. Нет истории/поиска сообщений. | Прямо противоречит требованию "независимо от того, включён ли ноутбук владельца" — годится для интерактивной работы за ноутбуком, но НЕ как канал управления для облачных cloud routines. Для автономного конвейера нужен отдельный webhook/сервер. |
| GitHub Actions (scheduled workflow / repository_dispatch) как мост Telegram → GitHub Issues | AVAILABLE | Бесплатно в рамках квоты 2000 мин Actions/мес (приватные репо, GitHub Free). Минимальный интервал cron — 5 минут (не realtime), возможны задержки в пиковые нагрузки; для приватных репо нет 60-дневного отключения по неактивности. | Кастомный workflow может по расписанию дёргать `getUpdates` и через `gh` CLI/REST API создавать Issues. Готовые примеры (appleboy/telegram-action) закрывают только направление GitHub→Telegram; обратное (Telegram→Issue) нужно писать самим. | Органичный для архитектуры вариант — не плодит лишние сервисы, использует уже выбранный GitHub, но задержка 5+ минут может быть неприемлема для UX "написал боту — сразу пошла работа". |
| Cloudflare Workers (serverless-функция как webhook-мост Telegram → GitHub API) | AVAILABLE | Бесплатный тариф: 100 000 запросов/сутки (≈3 млн/мес), 10 мс CPU-времени на вызов — с запасом для лёгкого webhook-обработчика. Карта не обязательна. | Пишется вручную (JS/TS): принимает Telegram webhook (`setWebhook`) и напрямую дёргает GitHub REST API (создание Issue) через PAT. Realtime-мост без задержек cron и лимитов no-code платформ. | Лучший баланс "дёшево + быстро + без лишних абонплат" — мгновенно превращает сообщение/видео в GitHub Issue, работает 24/7 независимо от ноутбука. Требует немного кода. |
| n8n Community Edition (self-hosted, ноды Telegram Trigger + GitHub) | AVAILABLE | Софт полностью бесплатен навсегда (fair-code license), безлимитные workflows/executions. Платить нужно только за инфраструктуру хостинга (напр. дешёвый VPS). | Готовые ноды "Telegram Trigger" и "GitHub" из коробки (в т.ч. шаблон "Get GitHub issue updates → Telegram"); обратный сценарий Telegram→Issue собирается визуально. | Более дружелюбный вариант, чем serverless-код с нуля — визуальный конструктор, работает 24/7 в облаке; требует развернуть и поддерживать свой сервер n8n. |

Только 14-дневный free trial без карты, далее от $20/мес (Starter, 2500 executions/мес) при годовой оплате. | Те же ноды Telegram/GitHub, без забот о хостинге. | Не подходит при ограниченном бюджете как постоянное решение — либо от $20/мес, либо self-hosted Community Edition. |

## Рекомендация для MVP

Цель Фазы 0 — минимальный работающий стек для ОДНОГО бренда (ROMAN) в режиме ROMAN RAW, без лишних платных слоёв, там где есть бесплатная/дешёвая прямая альтернатива с подтверждённым API.

### Ядро автоматизации
- **Claude Code + Claude Agent SDK** (в рамках уже оплачиваемой подписки Pro/Max) — основной "мозг" конвейера: транскрипция → выделение моментов → генерация сценария/хуков/подписей → QA версий под площадки.
- **Модели**: Haiku 4.5 для дешёвой массовой постобработки (чистка транскрипта, таймкоды, грубая классификация моментов), Sonnet 5 — для творческих задач (сценарий, хуки, подписи) и финального QA. Opus 5 держать в резерве для сложных редакторских решений, не включать в дефолтный путь по бюджету.
- **Claude Code Cloud Routines** — статус LIMITED (research preview), но это единственный подтверждённый способ выполнять шаги конвейера в облаке без включённого ноутбука. Использовать через Schedule (cron) и API-триггер (`/fire`), не полагаясь на нативный GitHub-триггер (он не покрывает Issues).
- **Google Drive MCP-коннектор** — хранилище сырых и готовых видео (AVAILABLE, бесплатно). S3/R2 откладывается на потом — по нему статус UNKNOWN, нет проверенного официального коннектора.

### Командный центр и очередь задач
- **GitHub (приватный репозиторий)** — Issues как очередь задач, PR/commits как результат, как и задумано в ТЗ.
- **GitHub Actions** — мост "Issue создан → Routine API `/fire`" (AVAILABLE, бесплатно в рамках квоты минут). Это закрывает разрыв, что нативный GitHub-триггер Routines не реагирует на Issues.

### Мост Telegram → GitHub
- **Реализовано:** код моста написан и типизирован — `apps/telegram-bridge/` (см. `docs/adr/003-automation-executor.md`), ждёт только деплоя (аккаунт Cloudflare у владельца).
- **Cloudflare Workers (Free plan)** как realtime-webhook-мост: Telegram `setWebhook` → Worker → GitHub REST API `POST /repos/.../issues`. Это единственный вариант из проверенных, который одновременно (а) бесплатен, (б) realtime (не 5–15-минутный cron, как GitHub Actions/Zapier/Make), (в) не имеет коммерческих ограничений ToS (в отличие от Vercel Hobby) и (г) не требует карты при регистрации (в отличие от AWS Lambda). Официальный плагин `telegram@claude-plugins-official` для этой роли не подходит — он требует постоянно запущенной локальной сессии Claude Code, что прямо противоречит требованию "независимо от ноутбука".
- **Telegram Bot API** напрямую (не через сторонние агрегаторы) — бесплатно, но с ограничением на скачивание/загрузку файлов (загрузка до 50 МБ; скачивание через `getFile` — подтверждено эмпирически: ровно 20 МБ). **На старте MVP видео стоит передавать не через тело Telegram-сообщения, а как ссылку** (Роман загружает видео в Google Drive и присылает боту ссылку, либо использует короткие тестовые ролики) — разворачивать Local Bot API Server ради снятия лимита на этапе MVP избыточно по инженерным трудозатратам; вернуться к этому, если объём/размер исходников это потребует.

### Транскрипция
- **Обновлено (ADR-004 v2, решение владельца):** ни Deepgram, ни любой другой платный облачный сервис — владелец явно отклонил создание очередного стороннего аккаунта. Выбран **self-hosted Whisper** (`faster-whisper`, открытая модель, без API-ключа/карты/аккаунта) — реализован в `scripts/transcribe.py`, протестирован на реальной речи. Исходная рекомендация ниже сохранена как справочная (что рассматривалось и почему) — Deepgram Nova-3 был бы самой дешёвой платной опцией ($0.0043–0.0077/мин, $200 бесплатного кредита), резерв — AssemblyAI/OpenAI Whisper API, но ни один из них не выбран.

### Монтаж (нарезка, субтитры, B-roll, версии под площадки)
- Для MVP с ограниченным бюджетом — **FFmpeg-based self-hosted решения** (напр. на базе `artbyjazi/autoclip` или собственный FFmpeg-пайплайн), запускаемые внутри той же облачной Claude Code Routine/GitHub Actions runner. Это единственный вариант в категории со статусом AVAILABLE и нулевой лицензионной стоимостью — требует больше инженерной работы на старте, но не создаёт ежемесячных подписок.
- **Opus Clip и Submagic откладываются на потом**: оба дают отличную готовую детекцию "лучших моментов" и API, но программный доступ у обоих закрыт за платными планами ($69/мес у Submagic, "по запросу" Business-план у Opus Clip) — пересмотреть, когда будет понятен доход/объём контента и FFmpeg-пайплайн начнёт давать сбои по качеству.
- **Shotstack** — держать в уме как опцию для финального рендера версий под конкретные аспекты (9:16 и т.д.), если самодельный FFmpeg-пайплайн окажется слишком трудозатратным; бесплатных 20 минут хватит на тестирование интеграции перед решением.
- **CapCut API — исключить из плана полностью**: официального API для этой задачи не существует (NOT_AVAILABLE).

### Публикация
- **YouTube Data API v3** — подключать сразу, AVAILABLE и бесплатно, лимита ~100 загрузок/день заведомо достаточно.
- **Facebook Reels API** — подключать сразу при условии, что бренд ROMAN оформлен как Facebook Page (стандартная практика); AVAILABLE и бесплатно.
- **Instagram Graph API** и **TikTok Content Posting API** — оба AVAILABLE по цене (бесплатны), но оба требуют пройти модерацию заранее (App Review Meta 2–4 недели / TikTok-аудит 2–6 недель, до аудита посты приватные). **Это единственный по-настоящему時-критичный пункт всего аудита: подавать заявки на Instagram App Review и TikTok Content Posting API нужно в первый же день Фазы 0**, не дожидаясь готовности остального конвейера, иначе MVP на этих двух площадках первые недели будет публиковаться вручную.
- **X (Twitter) API** — статус PAID без бесплатного пути, но при низком объёме постинга стоимость — центы/доллары в месяц; подключать по мере готовности, не приоритет первой недели.
- **Оркестрация публикации между площадками — n8n Community Edition (self-hosted)** на дешёвом VPS (~$5–7/мес), а не платные агрегаторы Metricool ($53/мес) или Ayrshare ($149/мес): n8n дёргает напрямую бесплатные официальные API (YouTube, Facebook, и далее Instagram/TikTok после модерации) без дополнительной абонплаты за сам факт агрегации. Buffer Free (AVAILABLE, 3000 запросов/30 дней) можно рассмотреть как более простую альтернативу n8n на самом старте, но сначала стоит пилотно проверить, действительно ли Buffer поддерживает Reels-формат — это не подтверждено документацией.

### Что откладывается на потом (не входит в MVP)
- **AI-аватар и голосовое клонирование (HeyGen, ElevenLabs, Synthesia)** — вся категория `avatar_voice` осознанно вне MVP: ROMAN RAW по определению работает с реальным сырым видео Романа, "манера речи" сохраняется естественно через сам факт использования его исходной записи. Клонирование голоса (ElevenLabs Starter, ~$6/мес) стоит подключить в следующей фазе, когда понадобится масштабирование без съёмок или мультиязычные версии — это единственный из этой категории пункт с низким входным порогом, остальные (HeyGen Digital Twin Enterprise, Synthesia) явно выходят за рамки "дёшево/бесплатно".
- **S3/R2 хранилище** — Google Drive MCP закрывает потребность MVP; переходить только если ограничения Google Drive API/квот станут проблемой.
- **Metricool, Ayrshare** — платные агрегаторы публикации, пересмотреть только если самостоятельная оркестрация через n8n не будет справляться с объёмом.
- **Local Bot API Server** для снятия лимита на размер файла в Telegram — включать только если передача видео через ссылку на Google Drive окажется неудобной на практике.
