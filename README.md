### Публикация картинки в Instagram — быстрый пример

Есть готовая картинка + публичный URL, откуда Instagram сам её скачает (сама картинка на диске нужна только для проверки и защиты от повторной публикации — путь может быть любым, необязательно из `state/content_drafts`):

```bash
python scripts/publish_instagram.py \
  -i "путь/к/картинке.jpg" \
  -u "https://публичный-адрес/картинка.jpg" \
  -a roomsgold3 \
  -c "Текст подписи"
```

- `-i/--image` — локальный файл (для хеша/защиты от дублей, любой путь).
- `-u/--image-url` — публичный HTTPS-адрес, который реально скачает Instagram (у нас пока нет автозагрузки в публичное хранилище — см. `docs/IMPLEMENTATION_PLAN.md`; если своего хостинга нет, можно закоммитить файл в этот же публичный репозиторий и использовать `https://raw.githubusercontent.com/Tima77777777/roman-ai/main/<путь>`).
- `-a/--account` — `roman.demidov.official` или `roomsgold3`.
- `-c/--caption` — подпись (необязательно).

Одна и та же картинка может быть опубликована в оба аккаунта отдельно — `publish_guard` считает их разными публикациями (защита от дублей работает в паре файл+аккаунт, не только по файлу).

## Управление

Владелец (Роман) ставит задачи через Telegram-бота (`@MyClaudhelp55555_bot`). С 2026-09-04 сообщения идут через вебхук: Telegram → Cloudflare Worker (`telegram-bridge`) → GitHub Issue → webhook-триггер будит Cloud Routine "Telegram poller" — без polling, реакция за секунды. Часовой `getUpdates`-опрос отключён, оставлен как резерв. См. `docs/ARCHITECTURE.md`, раздел 3 (3.2 — текущая схема, 3.1 — устаревший резерв).
