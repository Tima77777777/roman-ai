# Security

## Секреты

Все токены/ключи живут только в `.env` (см. `.env.example` для полного списка переменных) — файл в `.gitignore`, никогда не коммитится. Скрипты пайплайна читают их через переменные окружения и понятно падают, если секрет не задан, вместо непонятного краша (см. `scripts/publish_youtube.py`, `publish_facebook.py`, `download_from_drive.py`).

Для git push используется repo-scoped credential helper через `gh` (`git config credential.https://github.com.helper "!gh auth git-credential"`), а не токен, вставленный в URL/команду — токен читается из `.env` в переменную окружения непосредственно перед вызовом.

## Owner-only allowlist

И локальный `CronCreate`-поллер, и (в перспективе) Cloudflare Worker-мост обрабатывают команды **только** от `TELEGRAM_OWNER_ID` — сообщения от любого другого Telegram-пользователя игнорируются молча (см. `docs/ARCHITECTURE.md`, раздел 1.3, и `apps/telegram-bridge/src/index.ts`).

## Политика автономных действий

`policy.json` + `scripts/policy_check.py` формализуют, какие действия исполнитель может выполнять сам (`always_allowed`), а какие обязан вынести на решение владельца (`requires_owner_approval`, дефолт для всего неизвестного).

## Известные временные отклонения от нормы

- **Репозиторий сейчас public**, а не private. Причина: не удалось (пока) подключить GitHub App к claude.ai Routines через доступный UI (см. `docs/ARCHITECTURE.md`, раздел 3.2). Секретов это не касается (см. выше) — раскрыт только код и текст ТЗ/стратегии. Возврат в private — открытая P0-задача (`docs/IMPLEMENTATION_PLAN.md`).
- **Текущий GitHub-токен считается скомпрометированным** — засветился в переписке. Ротация — открытая задача, ждёт действия владельца (создать новый токен со scope `repo` + `workflow`, отозвать старый).

## Отчётность

Каждая обработанная задача (через Telegram) сопровождается ответом владельцу со статусом (что сделано / что нет / что требует решения) — см. `docs/ARCHITECTURE.md`, раздел 1.3, и формат отчёта в разделе 7 `docs/TZ_AI_Company_Hybrid.md`.
